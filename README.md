# Issue #1788 Windows 实包验收

运行载荷来自 `471b56a4bbe45f331902adeb6c03ca99d19bb30c`。第一片安装器源码为 `7039d70ec6c8b2750ff19b80861f793df941c618`，脚本前置后的源码为 `2b271b8670c8858de3a4b8e8ed2844d6952212aa`。两个提交只改安装器与其测试，A/B 编译时复用同一份冻结载荷。

旧版是 1.14.0 的 `917120d55bb5bf618a3cc49c0749d5f5172ace46`。从 SHA-256 为 `0acd44e26c5750b82c0427257acf5e6154396b6aa4f51385fe7efc446e69b820` 的原始 EXE 取回六个归档及五份清单，逐个匹配原构建清单，再用同一提交的安装脚本生成测试专用 AppId 旧包。实验采用 Windows 11 10.0.26300、i5-12600KF、Inno 7.1.0 32 位 Setup / x64 安装模式，Defender 实时保护开启，未清空系统缓存。A/B 的启动前 CPU 采样分别为 37% 和 19%，先后顺序为 A、B。

两次从同一停止的旧安装、同一测试文件锁和同一安装目录开始。A 在 Inno 占用提示处取消。B 在释放自己持有的文件锁后选择继续，原生文件占用检查仍执行。约 1.9 秒的收益只归于该轮身份脚本提取，另一次同载荷对照为 1,781 ms 降至计时分辨率以内。

最终 B 点击到正式安装 12.631 秒，旧载荷清理 15.656 秒，依赖归档校验 2.130 秒、展开 29.355 秒，共 56,143 个归档条目。其他归档与后置步骤见测量文件。两个覆盖样本的替换和展开耗时波动较大，本次保留既有删除、归档及完整性策略。

原旧包覆盖的准备页截图仅有 Inno 通用状态。最终 B 截图记录身份检查、等待退出和 Inno 文件占用提示。脚本的 Ready 回调与像素采样是两套时间源。回调的 1–2 ms 来自点击观测器与 Setup 日志，截图确认的是同步等待期间实际可见的标签。

恢复实验覆盖旧包回装、身份不匹配拒绝、归档摘要故障。归档故障载荷本身保持一致，实验仅将清单摘要置零。故障包由提取器返回 1，Setup 返回 5，未继续解开下一份归档。生产配置 EXE 另行编译并核对六个归档和五份清单，实机运行使用专用 AppId。

有效 B 修复后，应用独立启动 44.349 秒到 ready，通过真实 Electron 会话读回同一个测试线程及记忆版本。配置、普通文件、合成认证与客户端历史文件的哈希保持一致。实机首装在移除测试 AppId 注册后使用全新程序和数据目录，点击至正式安装 3.430 秒，安装及后置步骤 67.902 秒，另行首启 43.700 秒到 ready。旧版首启的独立样本在 125.073 秒触发 API 就绪超时，两者启动状态与缓存条件不同。真实外部模型账号及其他 Windows 版本留待验收。
