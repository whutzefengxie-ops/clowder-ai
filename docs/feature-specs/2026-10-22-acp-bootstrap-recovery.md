# 自定义 ACP 客户端的安全目录选择与恢复

来源：PR #1677 的 Windows owner 拒绝报告，以及用户要求“不修改系统盘 ACL、不降低安全性，覆盖自定义 ACP client，补齐失败重试并端到端验证”。

Before：插件能安装和绑定，但启动在 Host 目录检查处失败；用户不知道如何找到合格目录，失败还可能被永久缓存。
After：Host 自动尝试严格校验的候选；用户也可在现有客户端配置中检查、选用明确目录。条件修复后再次发送即可重新构建服务。

Architecture cell：既有 ACP bootstrap / 插件客户端配置 / 按需服务生命周期。Map delta：none。目录安全属于 Host，不由插件声明或用户点击绕过。

## 不变量

- 任意客户端可以尝试数据卷候选，但未经审计的启动链始终使用原完整校验；不扩大可信 SID、不修改已有目录 owner/DACL、不把普通路径当真实卷根。
- 用户指定的目录必须是本机绝对路径，使用严格校验，不自动改选路径。原有经过审计的自动回退特例保持原边界。
- CLI 和 UI 检查复用生产校验器；只创建新的私有 bootstrap root/cwd，不启动客户端，不读取认证，不修补已有 ACL。无合格目录时明确拒绝，不承诺“新建 D 盘文件夹”能修复祖先权限。
- 创建成功的服务继续缓存；失败/null 仅撤销对应构建的缓存，下次显式调用重试。不自动循环重试、不重复发模型请求、不让旧失败清除更新配置的构建。
- 新 root/cwd 及真实 spawn 前继续复验；私有目录自身被破坏时立即拒绝，不用迁移掩盖。

## 工作单元与验收

1. 严格候选与显式目录：先红后绿测试非审计链候选、错误分类、显式路径拒绝和原有安全负例。
2. 服务恢复：覆盖 throw/null、并发去重、旧构建失败和配置更新竞争；通过真实适配入口观察结果。
3. 用户路径：复用设置 → 插件 → 客户端配置，增加可选引导目录和检查动作。检查反馈区分进行中、成功、失败；提供同一检查器的 CLI。
4. 端到端：独立实例和任务原生 HOME，安装 packed 插件，验证自定义协议夹具失败后恢复，以及 dsh/Claude/pi 的真实 ACP/MCP 调用。原企业机未连接，不能冒充其验收；本机未安装 CodeAgent 时明确区分协议夹具与真实 CodeAgent。
5. 交付：更新原两份操作文档；按当前 diff 跑 `pnpm biome check <修改文件>`、shared/API build、Web 类型检查及受影响测试，独立安全审查后推送并回读 PR #1677。插件文档若变化同步 PR #104。

用户无需猜权限：先保持目录为空使用自动选择；失败时点“检查引导目录”查看实际原因，可填写候选绝对路径再检查。全部卷均拒绝时需要管理员提供祖先同样安全的专用存储位置；本功能不接管系统目录，也不提供跳过校验开关。
