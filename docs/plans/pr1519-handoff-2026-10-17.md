## 3. 当前阻塞与根因

本轮尚未产出基于 `aae33b55b` 的新 EXE，原因如下：

1. 构建机 DNS 当前不可访问，Corepack 无法下载 pnpm，冻结工作区安装会请求 npm 镜像。
2. 使用本机已缓存的 pnpm 和同版冻结工作区继续后，Sharp、better-sqlite3、node-pty 等导出阶段已运行；随后构建在 `desktop/scripts/frozen-dependency-resolution.mjs` 创建 `dependencies -> node_modules` 的 junction 时失败，错误为 Windows `EPERM`。
3. 该错误发生在本机权限/符号链接能力，不等同于新的业务代码失败。需要在允许创建 junction 的构建环境中复跑，或让打包脚本提供不依赖 junction 的受控回退；后者必须先单独设计和测试，不能临时把旧包改名交付。
4. `@larksuite/cli` 的下载型 postinstall 在离线环境失败。本轮只用临时 shim 跳过该下载，未把这个本机绕过写进提交；正式 CI/发布环境仍应按正常安装流程执行并验证其二进制是否完整。
