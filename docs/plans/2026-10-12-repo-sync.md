# 单向 Git 接收与流程界面实施计划

来源：Issue #1582 的新版方案与维护者回复，以及用户确认：同一 worktree、同一分支、一个 PR 完整交付；内部先走 Git 路径，不依赖 CodeHub CLI。

目标：补齐共享 Issue 和合入中断的可交互原型，并在同分支实现可运行的 Git 接收执行器。内部核心只接受上游交付；内部定制位于独立插件。原始对象保留，两侧 main SHA 允许不同。

## 交付合同

- 已有仓登记上游 U0 和内部 I0，完整 SHA、分支 HEAD 与 Git tree 核验通过才启用。
- 上游只读获取；内部只推送 `sync/<delivery_id>`，不推 main，不自动合入。
- 发现以连续 main 接受边界为准；GitHub PR、Issue 与 commit 数据通过只读 gh API 获取。无法确定来源或关闭关系时暂停，不自动推断。
- 每笔冻结来源、目标、原始提交与候选 head；未完成交付优先恢复，不能因游标前进丢失。
- 合入后核验 tree(U)=tree(I)、U 与上一内部接受版本均是 I 的祖先、冻结候选已接受。未保存游标时可对账补写；结果冲突暂停。
- Issue 接收记录按对象聚合。一笔的应写记录成功即完成；有后续接收条件时保持 open，并允许下一笔。
- 内部 Git 不能创建 Issue/PR，也不能读取其状态、审批证据。提供来源模板及真实链接登记；人工在平台创建、审核、合入和核对状态，程序不伪称平台自动化已完成。
- 配置与台账留在用户指定的仓库外目录。单进程写锁，不自动接管未知旧执行器；意图先落盘，远端超时先回读。凭据使用 Git/gh 既有认证，不保存、不公开日志或正文中的凭据。
- 默认演示与真实执行隔离；真实服务显式用私有配置启动，界面展示真实模式。写接口限制 loopback Host/Origin 与会话令牌，不能由页面提交 shell 命令。

Architecture cell: 外置 repo-sync 执行器。
Map delta: new cell required（独立 packages/repo-sync，无应用 Host hook）。
Why: Git 与持久台账属于内部接收工具，不迁移应用核心生命周期或鉴权。

## 顺序与验证

1. 原型补齐共享 Issue、恢复优先级、冲突暂停和接收状态文案；先观察行为测试 RED，再实现 GREEN。
2. 实现隔离 Git 工作目录、原始对象传输、候选构造、分支回读与接受核验；用临时虚构 Git 仓验证独立快照和连续 U1/U2。
3. 持久台账、单写锁、冻结交付、对象登记及三种中断点恢复；重新启动执行器验证，失败不重复推送或丢失交付。
4. 只读 GitHub 来源发现、CLI 与本地界面接入；内部平台手工入口明确，正常平台审核不可由本工具绕过。
5. 浏览器走共享 Issue 与恢复完整旅程；执行本次受影响的 Node 测试、Biome、diff 检查及独立审查。
6. 脱敏检查后推同一 feature 分支并创建/复用一个上游 PR，回读中文正文，附测试证据；不直接合入 main。

首版不支持 LFS/子模块，检测到就暂停。Git 路径不能验证原始 commit 的平台关单语义，因此实际接入需用户提供已验证的平台能力声明；没有声明不得推送。Git tree 相同不能替代可构建性，配置的核心和插件检查须针对冻结候选运行并绑定其 SHA。
