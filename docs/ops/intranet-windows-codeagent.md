# Clowder AI Intranet 使用说明

这是独立内网发行版。安装名称、安装目录、用户数据目录与普通版分开；不迁移或覆盖普通版的角色、配置、认证和历史。CodeAgent 的接入逻辑直接内置 Host，无需安装 ACP 插件。

本说明用于这个独立内网包；公共 Host 的严格默认值不因此改变。公共策略的完整边界见 [Windows ACP 持久配置](./acp-trusted-host-compatibility.md)，本包操作以本说明及实际策略诊断为准。

## 安装与首次使用

1. 使用企业批准的方式安装并登录 CodeAgent。Host 包含 Node、Redis、Web 和桌面外壳，不包含企业 CodeAgent 程序本体或登录凭据。
2. 在 PowerShell 运行 `Get-Command codeagent -All | Select-Object Source`。应能看到实际的 `.exe` 或 `.cmd` 路径；`codeagent --acp` 是该客户端的 ACP 启动方式，通过 stdin/stdout 交换 NDJSON。手工启动后等待输入属于正常状态，检查结束可按 Ctrl+C 退出。
3. 安装交付的 `ClowderAI-Intranet-Setup-1.14.0.exe`，启动 **Clowder AI Intranet**。默认端口为 Web 5331、API 5332、Redis 6389。端口占用时先确认归属，不结束其他产品的进程。
4. 在首次创建伙伴或设置→成员→推荐配置入口重新检测。找到 CodeAgent 后，会优先推荐宪宪、砚砚、墨墨三套独立身份；点击“一键创建 3 位伙伴”。同一个 CodeAgent 程序承载三个角色，不代表三个不同的底层模型。
5. 若已安装其他客户端，可按需要勾选。已有角色不会自动改绑、覆盖，已有同名身份也不会自动重复创建。客户端缺失时显示“未检测到”，不能据此推断登录或 ACP 协议已经验证。
6. 在会话中分别 `@宪宪`、`@砚砚`、`@墨墨` 发起任务；从一个角色向另一个角色传球，再检查实际伙伴回复，以验证协作链路。

CodeAgent 如果安装在自定义位置，优先把安装目录加入用户 PATH 并重启本应用后重新检测。也可在成员编辑器手动新增/编辑通用 ACP，填写第一步找到的可执行绝对路径和 `--acp` 参数，选择对应角色模板；已经检测到的伙伴可点击“调整”修改启动配置。安装 CLI 后，已运行的桌面程序可能仍持有旧 PATH；退出并重新启动后再检测。

## 已安装过多个测试包时怎样更新

正常更新采用**同一程序目录覆盖升级，不先卸载**。安装器先校验并保留实例标识，受控停止目标安装的进程，然后清除该目录的旧 Node、API、Web、Electron 等程序负载并重新解压，避免已删除模块残留；无法确认身份或停止目标时应报告失败。默认用户数据根在程序目录之外，配置、认证和历史不属于这些替换目录。

内网发行版使用固定 AppId。Inno Setup 默认复用同应用登记的上次安装目录，不能把改版本号或另选目录理解成完整隔离，见 [AppId](https://jrsoftware.org/ishelp/topic_setup_appid.htm) 与 [UsePreviousAppDir](https://jrsoftware.org/ishelp/topic_setup_usepreviousappdir.htm)。两个程序目录仍可能使用同一个默认数据根与端口，开始菜单或卸载登记也可能只指向其中一个。

根据当前单实例启动逻辑，旧进程仍持有同一用户数据根的锁时，运行新目录的 EXE 可能只激活旧窗口，新进程随后退出；看到窗口打开不能证明新版本已运行。因此第 1、3、5 步的真实路径、完整退出和构建 SHA 核对不可省略。

升级前后按以下顺序核对：

1. 从当前快捷方式“目标”或任务管理器确认实际 `desktop-dist\Clowder AI.exe` 路径，其上一级就是程序目录；不要只看安装包文件名或相同的 `1.14.0`。
2. 只读查看程序目录的 `desktop-instance.json`；老布局可能位于 `desktop-dist\desktop-instance.json`。记录 `CAT_CAFE_DESKTOP_INSTANCE_ROOT` 与三个端口。没有 marker 且没有启动环境覆盖时，同一 Windows 用户默认使用 `%LOCALAPPDATA%\Clowder AI Intranet` 和 `5331/5332/6389`；仍以启动诊断为准。
3. 用应用菜单/托盘“退出”完整关闭目标环境，确认数据根后备份其配置和持久数据。仅关闭窗口可能只是隐藏到托盘。不要按进程名称批量结束 Node/Redis。
4. 将新包装回第 1 步确认的同一程序目录，保持原实例参数。不要为了升级换数据根、删除 marker 或先运行旧卸载器。
5. 启动后核对程序路径、数据根、端口及包 manifest 的源码 SHA。程序目录中的 `packages\api\dist\.build-commit` 与 `packages\web\.next\.build-commit` 应与该交付 SHA 一致；缺失或不一致时先报告，不能作为新版本验收。再回读原角色、历史和会话绑定。

全新首装验收使用独立虚拟机，或由交付方明确生成具有独立发行身份、程序/数据目录和端口的隔离验收包；换目录安装同一内网包不算干净隔离。保留旧程序时明确哪一个可启动、哪个只作回退，先盘点后再决定清理。

**当前限制：** 上述历史 EXE 同目录升级证据来自 `3d1d78994` 包，不能替代本轮新源码安装验收。只读检查还发现，自定义数据根落在程序目录的 `bundled` 或 `cat-cafe-skills\.cat-cafe-shared-refs` 下时，与卸载或升级递归清理范围重叠；现有拒绝清单未完整覆盖这两处。默认外置数据根不受这两个反例影响。新包发布前需要补齐保护和原生安装回归；旧卸载器不会因为源码已更新而自动获得新保护，相关特殊路径先保留，不直接卸载或搬迁。

## 工具与角色怎样对应

内网版“设置→成员→编辑成员”的“使用工具”只列 CodeAgent、Claude Code、Codex、DSH、Pi。这里选择 harness；角色名不是一个新的客户端。宪宪、砚砚、墨墨可以共同选择 CodeAgent，各自保留身份、职责、成员 ID 和会话。

一键检测后，在推荐伙伴的“调整”或成员编辑器中设置“身份与职责”：例如名字“小鲸鱼”、昵称“鲸鲸”。保存后，@ 候选、选中后的输入文本、消息里的提及和回复头统一显示“小鲸鱼 · 鲸鲸”。没有昵称或昵称与名字重复时只显示名字；内部 `dsh` ID 继续关联原来的配置和历史，不需要重建成员。已有 `@dsh` 消息只在界面投影为人类名称，不批量改写历史。显示名称与其他人的路由别名冲突时，仍使用可唯一识别的原别名，避免误投。

重新检测只刷新目录；选择当前相同工具不覆盖已保存的命令、参数和模型。切换到其他工具再返回，编辑器优先恢复这位成员原来的配置草稿。已有插件或特殊启动方式仍通过同一编辑器的“插件与已有接入配置”和原高级接入字段查看、选择与编辑；插件授权继续独立校验，不按程序名称自动合并。

本轮为源码调整，尚未生成新 EXE。首启 #1701、Pi #1706（Issue #1704）和 DSH 自定义 LLM #1707 已合入本轮源码；旧安装包不包含本轮新增体验，待用户确认后统一构建。

## DSH 已有自定义 LLM 如何接入

1. 在现有推荐伙伴的“调整”或“设置→成员→编辑成员”选择 DSH，打开“DSH 自定义 LLM”。此入口仅用于 Host 已识别的原生 DSH 启动入口；插件授权和任意自定义命令继续走各自已有配置。
2. “读取配置来源”优先选择你已经配置过的 `acp`、`desktop` 或 `web` profile，点击“读取 DSH 配置”。只读取运行 Host 的账号实际使用的 DSH HOME，不要求另配 `deepseek-official`。
3. 确认“供应商路由”和“DSH 模型”，点击“使用此配置”。Host 为这位成员生成独立 patch，并将启动参数加入草稿；这一步不调用模型，也不覆盖 DSH 原配置、认证或历史。
4. 可选点击“发送一次请求验证此配置”。这会实际调用模型，可能计费并留下 DSH 测试会话。随后点击成员页面“保存”；仅点击“使用此配置”还没有保存成员。
5. 重新打开成员确认启动参数，再在聊天中验证首轮与续聊。保存后的成员配置和 patch 会长期保留，重启无需重复选择。手改命令、参数、模型或切换接入后，旧验证回执会失效，需要重新读取确认。

没有可复用供应商时先在 DSH 添加接口与模型；内联密钥、表达式或未知启动包装器不能自动复制，按 [DSH 自定义 LLM ACP 指南](./dsh-custom-llm-acp.md) 处理。凭据继续由 DSH 的原有环境变量引用解析；Host 服务也需要能读取该引用。

## 兼容配置只需设置一次

本发行版每次启动默认带入以下设置，普通用户无需创建文件、编辑 `.env` 或逐个客户端设置：

```text
CAT_CAFE_INTRANET_EDITION=1
CAT_CAFE_TRUSTED_HOST_COMPATIBILITY=1
CAT_CAFE_WINDOWS_ACP_BOOTSTRAP_MODE=trusted-host
CAT_CAFE_ACP_BOOTSTRAP_CONFIG_AUDIT_MODE=warn-bootstrap-root
```

它们只影响 Host 的 Windows ACP 兼容策略。仍保留目录自身私有权限、本地 NTFS、链接拒绝、鉴权与直接本机管理边界；不会修改系统盘 ACL。审计失败例外只覆盖已存在 ACP client 的引导目录变更，不能用来修改命令、参数或 MCP 授权。

默认用户数据根为 `%LOCALAPPDATA%\Clowder AI Intranet`，审计目录为其中的 `data\audit-logs`。重启使用同一数据根，替换程序不覆盖用户文件。作者隔离验收可能使用安装参数指定的独立数据根；不要把验收数据根当作普通版路径。

运维人员需要显式覆盖时，在该数据根手工创建 `intranet-host.json`，例如：

```json
{
  "CAT_CAFE_WINDOWS_ACP_BOOTSTRAP_MODE": "trusted-host",
  "CAT_CAFE_ACP_BOOTSTRAP_CONFIG_AUDIT_MODE": "warn-bootstrap-root"
}
```

保存文件后完整退出桌面应用并重新启动。此文件优先于启动进程环境，其次是本发行版默认值。API 及普通启动流程只读取它，不自动改写；更新不覆盖。显式 `strict`、`required` 与自定义 `AUDIT_LOG_DIR` 均保留。不要在该文件放客户端认证或密钥。

## 引导目录与权限

引导目录是 Host 启动 ACP 进程时使用的专用目录，业务项目目录仍单独传给 ACP session。先用现有入口自动检查；需要手工指定时，选择当前用户可管理的本地 NTFS 目录，使用专门的子目录，保留服务端原生检查结果。不要对 `C:\`、`D:\` 或已有业务目录执行批量 ACL 修改。

内置 CodeAgent 默认自动选择，不要求用户先找目录。若另行使用原 ACP 客户端插件的高级设置：在 Host 本机打开“设置→插件→ACP 客户端目录”，引导目录先留空，点击“检查引导目录”，直接使用返回的完整路径；点击“使用此目录”后保存并重新进入页面回读。不要按示例用户名猜路径，也不要把检查返回的目录当作项目目录。这个高级入口属于可选插件，不是本包内置 CodeAgent 的安装前置步骤。

兼容模式仍可能拒绝目录自身权限或文件系统不合格的路径；它不能绕过 Windows 或 CodeAgent 本身返回的 EPERM。客户端 bypass 与 Host 兼容策略相互独立，本包不会暗中开启客户端 bypass。企业已验证的客户端参数可通过成员的 ACP 配置显式保存。

## 验证边界

后台的 Host、ACP 和 MCP 进程不应为日常使用打开命令窗口。本轮源码补齐了 ACP 进程隐藏窗口设置，并修正作者回归测试与开发监督器的窗口创建；只改变窗口显示，不改变 ACP 权限、命令参数或通信。旧安装包尚未包含这项修复，不能用源码测试替代新包验收。

安装、界面创建、持久化和合成 ACP/MCP 测试分别记录。`synthetic-client.cjs` 只是作者验收产物，不会进入安装包，也不是企业 CodeAgent。只有真实 CodeAgent 完成 ACP 初始化、MCP 工具调用、角色传球与重启续接后，才能声明企业客户端的完整实机验收通过。
