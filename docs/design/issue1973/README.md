页面上方是**设计演示控制区**，不属于拟议产品 UI。选择「正常发送」「失败重试」「断线恢复」，再操作聊天输入框中的发送按钮。底部「核对结果」也只是模拟控制，用于观察权威回执不同结果下的交互。

## 三条可操作旅程

1. **正常发送**：点击发送，立即见本人气泡；稍后模拟排队、收到，同一条气泡原位更新。
2. **失败重试**：模拟明确拒收，原文和附件卡保留；点击「重试」，原气泡恢复发送状态。
3. **断线恢复**：模拟结果未知，切换会话或刷新，原气泡仍在；点击「检查状态」只核查原身份，不增加发送次数。可将模拟核对结果设为「仍无法确认」，再改成「已交付给成员」，观察同一气泡收敛。

## 已验证的范围

[交互验证记录](interaction-verification.json) 覆盖上述三条旅程、切换/刷新、重复气泡、键盘恢复焦点、390px 无横向溢出、44px 恢复操作触区和减少动态设置。浏览器 console 无错误，原型没有外部网络请求。

这些验证只针对独立设计原型。演示使用 localStorage 保存合成文本和附件标志；附件卡不是持久化真实 File/Blob 的证明。延迟、队列、回执、重试和核查均为模拟，不能证明生产持久化、真实 HTTP/Socket 顺序、服务端幂等或 Agent 收到/已读，也不解释原事故完整性能根因。

正式修复仍需实现账号/thread 隔离的持久发送尝试、附件恢复、可靠身份对账和只读受理核查，并从真实发送入口验收。当前交付是设计，未修改产品代码或创建修复 PR。
